# AutoLike

Chrome Extension (Manifest V3), которое автоматически выполняет задания на сайте с заданиями:
находит задание → открывает TikTok → ставит Like / подписывается / смотрит → возвращается →
нажимает «Проверить» → ждёт результат и обновление баланса → переходит к следующему заданию.

## Установка

1. `chrome://extensions` → включить **Режим разработчика**.
2. **Загрузить распакованное расширение** → выбрать папку репозитория.
3. Войти в аккаунт TikTok в этом же браузере.
4. Открыть страницу с заданиями, нажать на иконку расширения → **Start**.

## Как работает

| Шаг | Что происходит |
|-----|----------------|
| Поиск задания | На странице ищутся карточки заданий (селекторы из настроек или эвристика), тип определяется по тексту |
| Открытие цели | Клик по кнопке сайта «Выполнить»/ссылке (сайт часто фиксирует клик). Если вкладка TikTok не открылась, ссылка открывается расширением |
| Действие | На TikTok ждём загрузки и нужных элементов, выполняем действие. Действия **идемпотентны**: если лайк уже стоит или подписка уже есть, повторный клик не делается |
| Возврат | Вкладка TikTok закрывается, фокус возвращается на сайт с заданиями (или страница открывается заново, если TikTok открылся в той же вкладке) |
| Проверка | Ждём появления активной кнопки «Проверить», нажимаем, анализируем **новый** текст в карточке, всплывающих уведомлениях и `alert()` |
| Баланс | После успешной проверки ждём роста баланса. Если баланс не изменился: ждём, перечитываем, перезагружаем страницу. Без роста баланса задание не считается выполненным (`behavior.requireBalanceChange`) |
| Повтор | При неудаче повторяем действие и проверку, но не больше `maxAttempts` (по умолчанию 4) раз |
| Провал | После последней попытки: уведомление, клик «Пропустить» (если кнопка есть), запись в список неудачных, переход к следующему заданию |

Уведомления внизу страницы:

- `✓ Задание выполнено`
- `↻ Задание не подтверждено. Повторная попытка 2/4`
- `✕ Не удалось выполнить задание после 4 попыток. Переходим к следующему.`

В popup: Start/Stop, статус, текущее задание, `Attempt N/M`, число выполненных и неудачных заданий,
баланс, список неудачных заданий и журнал.

### Защита от зацикливания

- ограниченное число попыток на задание (`maxAttempts`);
- ошибка любого шага (элемент не появился, таймаут, вкладка закрылась) тоже расходует попытку;
- задание, которое не удалось выполнить, больше не выбирается (список «Не выполненные», сбрасывается кнопкой в popup);
- если задания не найдены, страница перезагружается не больше `limits.maxEmptyScans` раз, затем остановка;
- необязательный лимит `limits.maxTasksPerRun`;
- все ожидания ограничены таймаутами (`timeouts.*`).

### Сохранение состояния

Состояние (фаза, текущее задание, номер попытки, статистика) хранится в `chrome.storage.local`.
Service worker будится каждые 30 с через `chrome.alarms` и продолжает работу с сохранённой фазы.
Если вкладка с заданиями перезагрузилась, выполнение продолжается с того же шага.
После перезапуска браузера выполнение останавливается, потому что id вкладок меняются.

## Архитектура

```
manifest.json
src/background/            — service worker (ES-модули), оркестрация
  index.js                 — точка входа: сообщения popup, события вкладок, keepalive, восстановление
  runner.js                — конечный автомат: select → open → perform → return → check
  phases.js                — константы фаз
  state.js                 — персистентное состояние (chrome.storage)
  context.js               — контекст шага (проверка Stop, паузы, запись состояния)
  config.js                — конфиг по умолчанию + переопределения из настроек
  taskTypes.js             — РЕЕСТР ТИПОВ ЗАДАНИЙ (распознавание + список действий)
  taskSelector.js          — выбор следующего задания, чтение баланса
  navigation.js            — переходы сайт ⇄ TikTok
  actions.js               — запуск действия на TikTok
  verification.js          — «Проверить» + подтверждение по балансу
  attempts.js              — политика попыток: успех / повтор / провал
  notify.js                — статус и уведомления
  tabs.js                  — вкладки, внедрение content-скриптов, RPC
  errors.js                — коды ошибок (фатальные / без повтора)
src/content/common/        — dom-утилиты, уведомления (Shadow DOM), RPC-мост
src/content/taskSite/      — драйвер сайта заданий: scanner (задания, кнопки, баланс), checker (проверка, пропуск)
src/content/tiktok/        — драйвер TikTok: actions (like, follow, view)
src/popup/                 — интерфейс расширения
src/options/               — редактор конфигурации (JSON)
tests/e2e.js               — e2e-тест с мок-сайтом и мок-TikTok
```

Content-скрипты внедряются программно (`chrome.scripting`) только во вкладку с заданиями и вкладку TikTok.
Они не хранят состояние и лишь выполняют команды background'а.

### Как добавить новый тип задания

1. `src/background/taskTypes.js`: добавить запись в `TASK_TYPES`:
   ```js
   {
     id: 'favorite',
     label: 'Избранное',
     match: ({ text }) => /(избранн|favorite|save)/i.test(text),
     actions: ['favorite']
   }
   ```
2. Если действие новое, добавить функцию в `ACTIONS` в `src/content/tiktok/actions.js`.
   Функция должна сначала проверять текущее состояние, затем кликать и возвращать `{ action, done }` или `{ action, alreadyDone }`.
   При ошибке функция бросает `dom.fail('код')`.

Если в тексте задания несколько действий («лайк и подписка»), они выполняются по очереди.

## Настройка под конкретный сайт

Селекторы для **tiktop-free.com** уже встроены в значения по умолчанию:
- карточка `.task-item` и id из скрытого поля `UserPerformTask[id]`;
- «Через браузер» `a.btn--complete2`, затем «Выполнить» `a.btn--complete`;
- `button[value="check"]` и `button[value="hide"]`;
- баланс `.user-balance`;
- ответ проверки в `#popup-task-error_message` и `#toast-container`.

В настройках хранятся только изменённые параметры. Поэтому новые селекторы из обновлений расширения применяются автоматически.

Если что-то не работает, нажмите в popup **«Копировать журнал»**. В журнале есть строки
`Проверка [статус] … ответ сайта: …` с тем, что сайт показал после «Проверить».

Откройте в popup **Настройки**. Это обычная форма с разделами.

| Раздел | Что настраивается |
|--------|-------------------|
| Основное | число попыток, лимит заданий, что делать с проваленными и непонятными заданиями |
| Проверка и баланс | засчитывать ли задание только при росте баланса, сколько ждать ответа, слова успеха и ошибки |
| Скорость и паузы | случайные паузы между шагами, время на TikTok после действия, пауза между заданиями |
| Ожидание загрузки | сколько ждать страницы, кнопок, капчи (увеличьте при медленном интернете) |
| Вкладки | открывать TikTok кнопкой сайта или напрямую, закрывать ли вкладку |
| Элементы сайта | CSS-селекторы карточки, кнопок и баланса (для tiktop-free.com уже настроены) |
| Элементы TikTok | селекторы кнопок TikTok (виден после включения «Показать расширенные») |

Устройство формы:
- у каждого параметра есть описание и значение по умолчанию;
- изменённые поля отмечены точкой, кнопка ↺ возвращает значение по умолчанию;
- неверное значение (например, ошибочный селектор) подсвечивается, и сохранить его нельзя;
- блок **«Проверить на странице»** показывает, какие задания, кнопки и баланс расширение видит на открытой вкладке, при этом ничего не нажимает;
- JSON-конфиг для опытных находится в свёрнутом блоке внизу.

Описание всех полей находится в `src/options/schema.js`. Чтобы добавить новую настройку в форму, достаточно одной записи там.

## Тест

```bash
npm install
npm run test:e2e
```

`tests/e2e-tiktop.js` повторяет разметку tiktop-free.com. Сайт в нём определяет нажатую кнопку формы по фокусу,
а ошибку показывает в модальном окне.

Тест запускает Chromium с расширением и мок-сайтом на 4 задания: лайк, подписка, «сломанное» видео
(должно провалиться после 4 попыток и быть пропущено) и задание, которое засчитывается только со 2-й проверки.
Тест также проверяет рост баланса.

## Ограничения

- Клики синтетические (`isTrusted = false`). Если сайт или TikTok начнут это проверять, понадобится `chrome.debugger` (Input.dispatchMouseEvent).
- Если TikTok покажет капчу, расширение ждёт до `timeouts.captcha`, пока её решит пользователь.
- Если TikTok требует вход, выполнение останавливается.
- Автоматизация действий может нарушать правила TikTok и сайта с заданиями. Используйте на свой риск.
